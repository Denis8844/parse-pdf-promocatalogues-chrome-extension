# Скачать каталоги — Chrome Extension (Manifest V3)

Расширение превращает рабочий JavaScript-скрипт «скачать каталог в PDF» (запускавшийся
вручную через DevTools на странице каталога) в удобное Chrome-расширение:

1. Вставьте одну или несколько ссылок на страницы каталогов (ридер) в popup-окно.
   Ссылки могут быть **относительными** — они автоматически дополняются до
   `https://www.promocatalogues.fr/...`.
2. Нажмите **«Скачать каталоги»**.
3. Расширение строго по очереди открывает каждую страницу, находит страницы каталога
   в панели миниатюр, загружает полноразмерные изображения (`zoomLargeWebP`),
   конвертирует их в JPEG (качество 0.92), собирает **один PDF на каталог**
   и скачивает его в стандартную папку загрузок Chrome.

---

## Установка

1. Сохраните папку проекта (или распакуйте `catalog-downloader-extension.zip`).
2. Откройте в Chrome: `chrome://extensions/`.
3. Включите **Режим разработчика** (тумблер справа вверху).
4. Нажмите **«Загрузить распакованное расширение» / “Load unpacked”**.
5. Выберите папку проекта (ту, где лежит `manifest.json`).
6. Готово — иконка расширения появится на панели инструментов.

Расширение одно и то же для Windows, macOS и Linux — отдельных сборок не нужно.
Для работы в режиме инкогнито включите расширение в настройках инкогнито-режима.

---

## Использование

1. Кликните по иконке расширения.
2. Вставьте ссылки на каталоги в текстовое поле. Ссылки можно указывать
   **относительными** (рекомендуется) — они автоматически дополняются до
   `https://www.promocatalogues.fr/`:

   ```
   /regardez/offres/catalogue-picard-3660147
   /regardez/offres/catalogue-castorama-3751268
   /regardez/offres/catalogue-la-redoute-3763748
   ```

   Разделители — новая строка, пробел, запятая, `;` или `|` — можно **смешивать
   в одном вводе**:

   ```
   /regardez/offres/catalogue-castorama-3751268 | /regardez/offres/catalogue-castorama-3455996 | /regardez/offres/catalogue-castorama-3455920
   ```

   Пустые строки игнорируются, дубликаты удаляются (в том числе если одна и та же
   ссылка введена и в относительном, и в абсолютном виде), пробелы вокруг ссылок
   обрезаются. Абсолютные ссылки на сайт тоже работают; неверные значения
   отбрасываются с пометкой.

3. Нажмите **«Скачать каталоги»**. В popup отображается прогресс:

   ```
   Каталог 2 из 5
   Страница 8 из 24
   ████████████░░░░░░
   ✓ Каталог 1 — скачан (файл.pdf)
   ⏳ Каталог 2 — обработка
   ○ Каталог 3 — ожидает
   ```

4. Окно popup можно закрыть — очередь продолжит работать в фоне (состояние видно
   при повторном открытии).
5. По завершении показывается итог: `Успешно: 8 · Ошибки: 2 · Всего: 10`.

Каждый каталог скачивается **отдельным PDF-файлом** с именем по логике исходного
скрипта: `Название_каталога_3766479_2026-08-28.pdf` (заголовок страницы без хвоста
сайта + номер каталога из ссылки + дата; при пустом заголовке — последний сегмент
URL; если номера в ссылке нет — он просто не добавляется; номер не дублируется,
если уже присутствует в названии).

## Как это работает (архитектура)

```
popup.js ──START/STOP──▶ background.js (service worker) ──tabs.create──▶ вкладка каталога
   ▲                          │  очередь ссылок,                      │
   └──RUN_UPDATE (состояние)  │  последовательная обработка           ▼
                              │  chrome.scripting.executeScript  utils.js + pdf.js + content.js
                              │  tabs.sendMessage(CATALOG_START) ──▶  (на странице)
                              │                                       │ поиск [id^="overview-pages-"]
                              │                                       │ fetch zoomLargeWebP
                              │                                       │ canvas → JPEG (Q=0.92)
                              │                                       │ сборка PDF (вручную)
                              │                                       │ URL.createObjectURL(blob)
                              │  ◀──CATALOG_RESULT {blobUrl, filename}│
                              │  chrome.downloads.download(blobUrl)    │
                              │  ждёт onChanged (complete/interrupted)│
                              │  tabs.remove(вкладка) ────────────────▶ (blob-URL умирает)
```

### Роли частей расширения

| Файл | Роль |
|---|---|
| `background.js` | Service worker: очередь ссылок, строго последовательная обработка, открытие/закрытие технических вкладок, ожидание загрузки, внедрение content script, приём прогресса/результата, скачивание через `chrome.downloads.download`, состояние очереди в `chrome.storage.session`, рассылка обновлений в popup, keep-alive во время работы. |
| `content.js` | Перенос основной логики исходного скрипта: поиск `[id^="overview-pages-"]`, замена размера на `zoomLargeWebP`, fetch → `createImageBitmap` → canvas → JPEG (`Q = 0.92`), `jpegInfo()`, сборка PDF, blob-URL, имя файла. Работает **на самой странице**, поэтому сетевые запросы выполняются ровно так же, как в исходном скрипте (same-origin: куки, referer, без CORS). |
| `pdf.js` | Сборка PDF — дословный перенос алгоритма исходного скрипта (`DPI = 300`, `w = p.w * 72 / DPI`, xref-таблица, `/DeviceGray` для 1 компонента и т.д.). Без сторонних библиотек. |
| `utils.js` | `parseLinks()` (правила разбора списка ссылок) и `makeCatalogFilename()` (имя файла). |
| `popup.html/css/js` | Интерфейс: textarea со ссылками, счётчик, кнопки, прогресс, список ссылок со статусами, итог. |

### Почему PDF не передаётся по messaging

Chrome ограничивает размер сообщения расширения **64 MiB**, а сериализация сообщений —
JSON (типизированные массивы превращаются в массивы чисел с огромными накладными
расходами). Для каталогов из десятков страниц PDF легко весит десятки–сотни МБ,
поэтому передача байтов через `sendMessage` ненадёжна.

Решение: content script собирает PDF **прямо на странице** и создаёт `blob:`-URL
(`URL.createObjectURL`). По messaging передаётся только короткая строка URL + имя файла.
Service worker скачивает файл по этому URL через `chrome.downloads.download`, а
техническая вкладка остаётся открытой до завершения скачивания (blob-URL живёт,
пока жива создавшая его страница) и закрывается сразу после — память освобождается,
каталоги обрабатываются один за другим без перегрузки браузера.

`URL.createObjectURL` недоступен в service worker (crbug 1381188), поэтому создание
blob на странице — единственный способ избежать передачи больших данных. Offscreen
document здесь не требуется: он поддерживает только `chrome.runtime`, а байты всё
равно пришлось бы гонять через messaging с тем же лимитом 64 MiB.

### Массовое скачивание без предупреждений Chrome

Все файлы качаются через официальный **`chrome.downloads.download`** (Downloads API) —
по одному файлу за раз, с ожиданием завершения (`chrome.downloads.onChanged`) перед
переходом к следующему каталогу. Это стандартный механизм расширений и он не
вызывает браузерное предупреждение «Разрешить скачивание нескольких файлов?»
(оно относится к автоматическим скачиваниям со страниц через `<a download>`).

Настройка Chrome «Спрашивать, куда сохранять каждый файл» полностью поддерживается:
файл попадёт в диалог выбора пути, очередь дождётся решения пользователя
(с таймаутом 10 минут на файл).

Запасной путь: если `downloads.download` вдруг не примет blob-URL, расширение
использует скачивание через `<a download>` на самой странице — ровно как исходный
скрипт.

### Надёжность

- **Строго последовательная обработка**: одна вкладка за раз, никаких десятков
  открытых каталогов.
- **Ожидание страниц**: после загрузки вкладки content script опрашивает DOM до
  60 секунд (разумный timeout вместо фиксированной большой задержки) — панель
  миниатюр успевает подгрузиться.
- **Обработка ошибок**: ошибка одной ссылки (например, «страницы не найдены —
  открой ридер каталога» или «страница 12: HTTP 403») фиксируется в списке, и
  очередь переходит к следующей ссылке. В конце — итог.
- **Таймауты**: загрузка вкладки (60 с), одно изображение (120 с), обработка
  ссылки целиком (20 мин), скачивание (10 мин). Любой таймаут не останавливает очередь.
- **Keep-alive service worker**: пока очередь активна, SW каждые 20 с отправляет
  себе сообщение, чтобы Chrome не усыпил его посреди обработки.
- **Восстановление состояния**: очередь хранится в `chrome.storage.session`.
  Если Chrome перезапустит service worker, при следующем пробуждении очередь
  помечается остановленной с понятной ошибкой — зависших «призрачных» очередей нет.
- **Кнопка «Остановить»**: прерывает обработку текущего каталога (отменяет
  скачивание или сообщает content script об остановке) и завершает очередь.

## Настройки

Кликните на иконку шестерёнки в правом верхнем углу popup — откроется экран
настроек. Все параметры, которые раньше были доступны только правкой кода,
теперь изменяются прямо из расширения:

**Таймауты (в секундах):**
- открытие вкладки (30), загрузка страницы (60), внедрение скрипта (60),
  отправка команды старта (15), пауза после загрузки (0.6);
- поиск страниц каталога (60) — сколько ждём появления панели миниатюр;
- загрузка одного изображения (120);
- лимит на одну ссылку (1200 = 20 мин) — общий watchdog;
- ожидание скачивания PDF (600 = 10 мин), в т.ч. диалог «Сохранить как».

**Повторы и защита:**
- повторные попытки (2) — сколько раз повторять ссылку после технических сбоев;
- пауза между попытками (5 с);
- тишина до «проверки пульса» (60 с) — повторный старт при молчании страницы;
- heartbeat (150 с) — после скольких секунд без прогресса ссылка считается
  зависшей;
- восстановления после редиректов (3) — лимит навигаций-восстановлений.

**Качество изображений:**
- качество JPEG (0.92) — как в исходном скрипте; выше = больше размер файла.

Изменения применяются к новым ссылкам в очереди (включая повторные попытки).
Кнопка «Сбросить к значениям по умолчанию» возвращает заводские значения.
Настройки хранятся в `chrome.storage.local` и не сбрасываются при обновлении
расширения.

## Разрешения

```json
"permissions": ["tabs", "scripting", "downloads", "storage"],
"host_permissions": ["https://www.promocatalogues.fr/*", "https://promocatalogues.fr/*"]
```

- `tabs` — управление техническими вкладками;
- `scripting` — внедрение content script в открытые вкладки;
- `downloads` — скачивание PDF через Downloads API;
- `storage` — состояние очереди (`chrome.storage.session`) и настройки (`storage.local`);
- `host_permissions` — доступ только к promocatalogues.fr (относительные ссылки
  дополняются до этого домена).

## Известные ограничения

- Расширение рассчитано на **https://www.promocatalogues.fr** (относительные ссылки
  дополняются до этого домена; host_permissions ограничены им же). Ссылки на другие
  домены не поддерживаются.
- Расширение работает с теми же селекторами, что и исходный скрипт:
  `[id^="overview-pages-"]`, URL изображений `/flyers/<номер>/` и замена размера
  `260x270WebP|thumbnailFixedWidth|largeWebP` → `zoomLargeWebP`. Если сайт изменит
  разметку, понадобится обновить `content.js`.
- «страницы не найдены — открой ридер каталога»: ссылка должна вести именно на
  **ридер** каталога (там, где есть панель миниатюр), а не на карточку/обложку книги.
- Страницы, защищённые авторизацией: вкладка открывается в обычном профиле Chrome,
  поэтому скачивание работает, если вы уже вошли на сайт в этом профиле.
- Если сайт не успевает построить панель миниатюр в фоновой вкладке, включите
  галочку «Открывать вкладки каталога на переднем плане» в popup.

## Отладка

Если что-то зависло или пошло не так:

1. Откройте `chrome://extensions/`, найдите расширение «Скачать каталоги».
2. В карточке расширения нажмите на ссылку **«Служебный процесс» / “service worker”**
   (или «проверить представления»). Откроется консоль service worker'а.
3. В консоли расширение пишет фазы обработки: открытие вкладки, загрузка, внедрение
   скрипта, готовность PDF, завершение скачивания — с временем каждого шага.
   Это позволяет сразу понять, на каком этапе происходит задержка.
4. Ошибки ссылок (с текстом причины) показываются в списке popup.

Начиная с v1.2.0 встроена защита от «молчаливого» зависания, в v1.3.0 усилена:

- **offscreen keep-alive** — пока очередь работает, отдельный служебный документ
  «будит» service worker каждые 15 секунд, чтобы Chrome не усыпил его (MV3 усыпляет
  SW через ~30 с бездействия, что замораживало очередь без ошибок);
- таймауты на каждый шаг: создание вкладки (30 с), загрузка (60 с), внедрение
  скрипта (60 с), команда старта (15 с), одно изображение (120 с), ожидание
  скачивания (10 мин), общий лимит на ссылку (20 мин);
- **heartbeat**: если от страницы нет прогресса более 2,5 минут, ссылка считается
  зависшей и очередь переходит к следующей;
- если техническая вкладка упала (краш рендерера), ссылка сразу помечается ошибкой;
- **кнопка «Остановить» работает всегда и мгновенно**: отменяется текущее
  скачивание, контентному скрипту отправляется прерывание (оно обрывает даже
  выполняющийся fetch через AbortController), техническая вкладка закрывается,
  очередь финализируется с итогом — даже если service worker был перезапущен;
- **таймеры замирают**: «заняло: N» у завершённой ссылки и «всего: N» после
  окончания очереди показывают зафиксированную длительность, а не продолжают тикать;
- **ссылки показываются полностью**: в списке popup URL переносится по символам,
  не обрезается; у каждой ссылки есть иконка «копировать» — копирует относительную
  ссылку вида `/regardez/offres/catalogue-picard-3660147`;
- **повтор ошибочных ссылок одной кнопкой**: после завершения очереди в сводке
  появляется кнопка «Повторить ошибки (N)» — она запускает заново только ссылки
  со статусом «ошибка»;
- **диагностика**: в popup внизу виден номер версии расширения (v1.5.0) и кнопка
  **«Копировать журнал»** — она копирует журнал событий (этапы обработки, прогресс,
  ошибки с временем) в буфер обмена. Этот журнал можно прислать при проблемах.
- **восстановление после навигации**: если страница после внедрения скрипта перешла
  по новой ссылке (антибот-редирект, challenge-страница), расширение перехватывает
  навигацию, заново внедряет контентный скрипт и продолжает обработку — раньше
  скрипт умирал вместе с документом и ссылка «затихала» до heartbeat; при
  многократных редиректах (больше 3) ссылка прерывается с понятной ошибкой;
- **автоповтор ссылок**: после технических сбоев (таймауты, HTTP-ошибки, heartbeat,
  сеть) ссылка автоматически повторяется до 2 раз с паузой 5 секунд. Окончательные
  ошибки («страницы не найдены») не повторяются. Статус «↻» показывает повторную
  попытку, номер попытки виден в журнале;
- **«проверка пульса»**: если от страницы нет прогресса 60+ секунд, расширение
  повторно шлёт команду старта (безвредно, идемпотентно) — молча умерший скрипт
  оживает раньше, чем сработает heartbeat;
- контентный скрипт пишет ошибки доставки сообщений в консоль страницы
  (DevTools вкладки каталога) — при проблемах это видно напрямую;
- в popup показывается «прошло:» и время обработки текущей ссылки.
